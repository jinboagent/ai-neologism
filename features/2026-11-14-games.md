# Games — five lexicon word games, four languages

## 1. Requirement

From the site owner (2026-11-14, after the game prototypes in `game/gamesite`):

> 把这个游戏也做成四个语言的版本，然后在现在的主页上做一个游戏的板块，把这个游戏的页面链接进去，然后删除掉现在网页上的中文

Chosen scope (AskUserQuestion): **全部照搬** — port all five games, including the
semantic-ladder demo — and put the section **in the homepage AND the navigation**.

## 2. Problem / goal

The games existed only as a local FastAPI prototype (localhost:8765, English-only,
with Chinese characters on the antiquarium page). For the homepage section to link
anywhere in production, the games had to become part of the Next.js site — which
also satisfied the standing multilingual rule ("以后网站加其他功能都要考虑多语言").

## 3. Decided behavior

- **Architecture**: games live inside the Next.js app (not the FastAPI prototype,
  which stays as the local dev playground). The Python engine
  (`game/gamesite/lexicon.py`) was ported 1:1 to TypeScript.
- **Per-language data**: every game computes its rounds from the *viewing language's*
  published words (status='published' AND language=locale). The Daily Word is
  deterministic per (language, date) — same for every player of a language.
- **Availability detection**: a game only appears for a language when that
  language's data can fuel it. Morpheme games (fusion / flower order / reverse
  riddle) need `why_this_word` — today only English carries it at scale, so the
  German/Spanish/French antiquarium shows the Sator square + word chain plus a note
  explaining that the morpheme games light up once entries carry their etymology.
  No hard-coding: re-running the per-language coin pipeline with `why_this_word`
  fills these in automatically.
- **Chinese removed everywhere**: the historical names are romanized
  (Lihe · Feihualing · Jielong, "Kong Rong's Lihe poems", "say hua"), matching the
  "Sator Square" treatment of proper nouns. Same cleanup applied to the FastAPI
  prototype templates.
- **Decoys** (Real or Fake?) are definitions of other real words in the same
  language; upgrading to the AI's rejected candidate definitions stays a future
  pipeline (as in the prototype).
- **Semantic ladder** stays an honestly-labelled demo: bank scores come from a
  seeded daily arc, typed guesses from the prototype's hash fallback; real scores
  need word embeddings (unchanged from the prototype's plan).
- **Deviations from the prototype** (deliberate): the "(mock)" streak text became a
  neutral "Noted" message (fake streak numbers don't belong in production); the
  "Powering data" scaffolding cards were dropped; the antiquarium hides empty
  sections instead of erroring.

Rejected alternatives: serving the FastAPI app behind a subdomain (new hosting,
CORS, no i18n infra) and static 4-language HTML exports (frozen rounds, no live
data) — both lose to in-app pages for a site whose core rule is per-language data.

## 4. Acceptance criteria

- [x] `/games` and `/games/<slug>` exist in all four locales (EN at the root,
      de/es/fr under `/{locale}`), registered in middleware redirects, sitemap and
      hreflang alternates.
- [x] Homepage has a games section (five cards) in all four languages; header nav
      has a Games entry for every locale.
- [x] Every game round is generated server-side per request from the published
      lexicon of the viewing language; no hardcoded word lists in components.
- [x] All player-visible strings come from the dictionary (games namespace in
      en/de/es/fr, type-enforced by `Dictionary = typeof en`).
- [x] No Chinese (or any CJK) characters render on any game page.
- [x] A language with thin data degrades gracefully: games grey out on the hub,
      vault sections hide, the morpheme note appears.
- [x] Gates: `tsc → vitest → eslint → e2e` all green.

## 5. Implementation

- **Engine** `src/lib/games/engine.ts` — pure port of `lexicon.py`:
  `parseComponents` / `validatedComponents` (why_this_word parsing, prototype
  parity including the hyphenated-word quirk), morpheme families + substring
  sweep, 5-gram index + `chainRound` (≥5-letter shared runs, safe distractors),
  category boards, `meaningPayload` / `realOrFakePayload` / `fusionPayload` /
  `reversePayload` / `flowerPayload` / `semanticPayload` (seeded via mulberry32),
  `dailyIndex` (Python `date.toordinal()` semantics), `availability()`.
- **Data** `src/lib/games/data.ts` — per-language published-words loader (60 s TTL
  cache on globalThis); `service.ts` — per-game payload getters + semantic banks
  (everyday words per language).
- **UI** `src/components/games/*.tsx` — five client components ported from the
  prototype templates (meaning-reveal, real-or-fake, category-sort, semantic-ladder,
  ancient-vault with five sub-games), restyled with the site's Tailwind tokens;
  `ui.tsx` holds shared chrome. Server shells: `src/components/pages/games-page.tsx`
  (hub) and `game-page.tsx` (dispatcher, exports `gameMetadata`).
- **Routes** — `src/app/games/page.tsx`, `src/app/games/[game]/page.tsx` and the
  `[locale]` mirrors (all `force-dynamic`); registered in `middleware.ts`
  (`LOCALIZED_PATHS`), `app/sitemap.ts` (`CHROME` + `LOCALIZED`), nav in
  `site-header.tsx`, games section in `home-page.tsx`.
- **Dictionary** — `games` namespace + `navGames` + per-game meta keys in
  `src/lib/i18n/{en,de,es,fr}.ts`.
- **Styles** — `.game-shake` keyframes in `globals.css` (with reduced-motion guard).
- **Tests** — `tests/lib/games/engine.test.ts` (31 offline tests on synthetic
  fixtures); games section in `scripts/test.mjs` (14 e2e checks).
